# TAKEN — product, design and engineering spec (v1.1)

Owner: Tom Baxter. Built 2026-10-12; Taken Pro and the four looks added in 1.1 (2026-10-13). This file is the contract every builder works to, with PRO.md for how Taken makes money.

## 1. The job

"It's the end of the day and I can't remember: did I take it today?"

Taken is a source of truth for a daily pill / supplement stack. Tap when taken. Look later and know for sure, with the time. Nothing else gets in the way.

Founder's words (verbatim, the bar): "Fucking frictionless. No ads, no text, no typing, literally tap, tap, tap, done." "All the apps I've seen are so complicated. You have to go through like a 20 step health funnel. It's interrupted by ads." "If I remember twice in a day, I can be like, oh, I actually did take them nine hours ago."

His stack (the first user): Vitamin D3 (daily), Finasteride (daily or every other day), Fish Oil (daily, 1 or 2 caps).

Non-negotiables:
- Zero onboarding funnel, zero accounts, zero ads, zero analytics/tracking, zero network calls of our own. Everything stays on the phone. Taken Pro (1.1) is bought through Apple's StoreKit, which talks to the App Store itself (3.9, PRO.md).
- Logging a dose = ONE tap from the app, the widget, the Lock Screen, Control Center, a notification, or Siri.
- Adding the stack needs no typing (quick-pick chips). Typing a custom name is optional.
- Opening the app answers the question in under one second: each item shows TAKEN + the exact time + how long ago, or PENDING.
- Tapping something already taken never un-takes it by accident.

## 3. Product

### 3.1 Single main screen ("TODAY")
One scrolling screen. No tab bar.

Top bar: wordmark `TAKEN` (mono, letter-spaced) left; date in mono `MON 12 OCT` + a settings/edit gear right.

Status header (the answer): big mono counter `2/3` with label `TAKEN TODAY`, a thin segmented progress bar (one segment per due dose). When everything due is taken: header flips to an `ALL TAKEN` locked state (signal colour, a short "lock-in" animation + success haptic). This is the dopamine moment; make it feel premium, not cartoonish.

Stack list: one row per item due today, in user order. Each row:
- a short mono code tag derived from the name (e.g. `VD3`, `FIN`, `FSH`, `MAG`), the full name, and the frequency in small mono (`DAILY`, `2X DAILY`, `ALT DAYS`).
- state right side: PENDING (dim, dashed outline circle) or TAKEN (signal colour, filled, `07:42` and `9H AGO` in mono).
- Tap a pending row: mark taken now. Light impact haptic, instant fill animation, a bottom toast `VD3 TAKEN 07:42 · UNDO` for 4 s (undo removes that dose).
- Tap a taken row: does NOT untake. It shows a small inline detail (`TAKEN 07:42 · 9H 12M AGO`) with a soft haptic. Long-press / context menu on any row: `Undo last dose`, `Set time…` (time picker to correct when it was actually taken, e.g. backfill "I took it at 7 this morning"), `Edit item`.
- Multi-dose items (2x/3x daily): the row shows dose pips (`●○`), each tap fills the next pip with its own timestamp; done when all pips are filled.
- Items NOT due today (every-other-day item taken yesterday) render in a separate dim `NOT DUE` group with `NEXT: TOMORROW`. Tapping still logs a dose (no lockout).

Locked mode (no Taken Pro after the first dose, 3.9): everything above stays on screen and readable. A slim mono bar under the status panel reads `START 7 DAYS ON US` (while the introductory offer applies) or `PRO ENDED · TAP TO CONTINUE`, and a tap opens the paywall. Logging a dose, TAKE ALL (its lamp becomes a small lock), Set time, backfill and adding items open the paywall instead, and the tap that opened it is applied once Pro is on. Undo, removing a dose, editing items, the day sheet and CSV export always work.

Primary action: when 2+ items are pending, a full-width `TAKE ALL` button (mono caps). One tap marks every pending due dose taken at the same time. With 0 pending it is hidden. Repeat guard: TAKE ALL (here and from a widget, the control, Siri or the nudge) and a widget row skip an item logged in the last hour, so a second tap never logs a 2x or 3x item's next dose on top of the first; the count on the button is what it will log. A tap on the row in the app is never held back.

History (below the list on the same screen): a 5-week contribution grid (Mon-first, today at bottom right), each cell = a day: fully lit (all due taken), half-lit (some), dim tick (none due or none taken), today outlined. Under it two mono stats: `STREAK 14D` (consecutive complete days, today counts once complete, a day with nothing due does not break it) and `30D 97%` (due doses taken / due doses, last 30 days). Tap a cell: a day sheet listing that day's items with their taken times; in the sheet each item can be marked taken (time defaults to 09:00 that day, adjustable) or a dose removed. This is the backfill path for "I forgot to log yesterday".

### 3.2 Empty state / first run
No onboarding screens. First launch shows the TODAY screen with an empty stack: a short line `NOTHING IN YOUR STACK` and a big `ADD TO STACK` button. That opens the Add sheet.

### 3.3 Add sheet (no typing)
A grid of quick-pick chips (multi-select, tap to toggle, mono caps). At least: Vitamin D3, Fish Oil, Omega-3, Magnesium, Creatine, Multivitamin, Zinc, Vitamin C, Vitamin B12, Iron, Probiotic, Ashwagandha, Melatonin, Collagen, Finasteride, Minoxidil, Metformin, Electrolytes, Vitamin K2, Folate, Calcium, Turmeric, CoQ10, L-Theanine. Each chip carries a sensible default code tag. Plus a `+ CUSTOM` chip that reveals a single text field (the only place typing exists). Frequency defaults to DAILY; a compact segmented control in the sheet sets frequency for the selected chips (DAILY, 2X DAILY, 3X DAILY, ALT DAYS). `ADD (3)` confirms. Target: Tom adds his whole stack in 4 taps.

### 3.4 Edit stack (from the gear)
Settings screen sections:
- PRO (after FEEL, before DATA): the status line (`FOUNDING MEMBER · PRO FOR LIFE`, `PRO YEARLY · RENEWS 12 OCT 2027`, `PRO YEARLY · ENDS ...` once cancelled, `PRO LIFETIME`, `TRIAL · ENDS 19 OCT`, `PRO MONTHLY · BILLING ISSUE` in a grace period, `NOT ACTIVE`), `SEE PLANS` when not active, `RESTORE PURCHASES`, `REDEEM CODE` (offer code sheet), `MANAGE SUBSCRIPTION` (Apple's sheet; hidden for lifetime and founding members), `TERMS OF USE` (Apple's standard EULA) and `PRIVACY POLICY`.
- STACK: list of items, reorder (drag), swipe to delete (with confirm), tap to edit name / code tag / frequency (DAILY, 2X, 3X, ALT DAYS, CUSTOM DAYS = weekday toggles) / archive. `ADD` row opens the Add sheet. Deleting an item keeps its past log entries out of stats but never crashes history. Settings never rewrite the past: a new frequency applies from today and earlier days keep the one they had; unarchiving keeps the archived days out of history (a dose logged for one of them still counts).
- REMINDER: one global nudge. Toggle + time (default 21:00). Copy: `If anything is still pending at this time, nudge me.` Ask notification permission only when the user turns this on.
- DAY STARTS AT: hour picker (default 04:00) so a 1 a.m. dose counts for the day you were living. All "today" logic uses this rollover.
- LOOK (after DAY, before FEEL): the four looks of section 4 as live swatches in a row, one tap each; the header names the look in use and the chosen swatch sits in brackets. The app recolours at once, the widgets and the control follow, and the app icon follows a moment later. Line: `The widgets and the app icon follow it.` There is no look picker at first launch.
- HAPTICS (FEEL): toggle (default on).
- DATA: `Export CSV` (share sheet; columns date, time, item, code), `Erase all data` (confirm).
- ABOUT: one line `Everything stays on this iPhone. No accounts. No ads. No tracking.`, version + build, Support link (https://tjbaxter.github.io/taken/). The Privacy policy link (https://tjbaxter.github.io/taken/privacy.html) sits in PRO, next to the Terms of Use.

### 3.5 Reminders (local notifications only)
- If enabled: at the nudge time, if any due dose for the current day is still pending, a notification `2 pending: VD3, FSH` with action buttons `TAKE ALL` (runs in background, no app open, marks all pending due doses taken now) and `OPEN`.
- Implementation must not nag when everything is done: schedule individual (non-repeating) requests for the next 14 days; cancel/reschedule today's whenever state changes (dose logged in app, widget, intent, notification action) and on every app foreground. Content lists what is pending as of scheduling, refreshed on every state change.
- Nudges follow Taken Pro (3.9): none are scheduled without it, and a subscription set not to renew is nudged only until it ends. A nudge's TAKE ALL while locked logs nothing, says `Logging needs Taken Pro. Open Taken to continue.`, and Taken offers that TAKE ALL with the paywall when it next opens.
- Each nudge carries its logical day. Its TAKE ALL logs only on that day: last night's nudge tapped this morning logs nothing and says so. Tapping a nudge opens the app on that day. Delivered nudges for earlier days, and today's once nothing is pending, are withdrawn on every reschedule.

### 3.6 Widgets (TakenWidgets extension, interactive via App Intents, iOS 17+)
- Home Screen small: big `2/3` + mini pips, and a single tappable `TAKE ALL` (or `ALL TAKEN` locked state).
- Home Screen medium: up to 4 item rows, each a Button(intent:) that logs that item's next dose; header counter.
- Lock Screen: accessoryCircular (gauge 2/3, or a check when complete), accessoryRectangular (up to 3 items with ●/○ and times), accessoryInline (`2/3 TAKEN` / `ALL TAKEN 07:42`). Make the circular/rectangular ones log `TAKE ALL` on tap via intent where the system allows; otherwise they deep-link into the app.
- Control Center (iOS 18+, `@available`): a ControlWidgetButton `Take all` with the app's glyph.
- Every write from a widget/intent calls `WidgetCenter.shared.reloadAllTimelines()` (and ControlCenter reload) and reschedules reminders. Timelines refresh at the next day rollover.
- Without Taken Pro (3.9) every widget shows the stack read-only with a small `PRO` lock glyph, its buttons give way to links, and any tap opens `taken://pro` (the paywall). A medium-widget row opens `taken://pro?then=log&item=<id>`, and that dose is logged once Pro is on. The timeline adds an entry at the moment cached Pro ends. The Control Center control reads the same cache (a ControlValueProvider): locked, it shows `Taken Pro` with a lock and logs nothing; the tap is kept and Taken offers it when opened (controls can only open an app through universal links, which Taken does not have).
- Widget visual style matches the app in the chosen look (its canvas, mono type, signal colour and radii), read from the App Group store with the stack (`WidgetSnapshot.theme`) and set as the environment's theme; `containerBackground(for: .widget)` is the look's canvas. Every family works in every look, including the iOS 18+ tinted and clear rendering modes (widgetAccentable on the signal elements; outside full colour, TAKE ALL is an outline and unlit segments stay faint, since every opaque fill renders white). Lock Screen widgets are drawn by the system in white and look the same in every look. The Control Center control takes the look's signal colour as its tint (its value provider reads the look with the Pro cache).

### 3.7 Siri / Shortcuts (App Intents, AppShortcutsProvider)
- `Take all` intent: phrases "Log my stack in ${applicationName}", "I took my pills in ${applicationName}". Result dialog: "Logged 3: Vitamin D3, Fish Oil, Finasteride."
- `Did I take it?` intent: phrases "Did I take my pills in ${applicationName}", "Check my stack in ${applicationName}". Dialog answers from the log: "Yes. Vitamin D3 at 7:42, Fish Oil at 7:42. Finasteride is not due today." or "Not yet: Fish Oil is pending."
- `Log item` intent with an AppEntity parameter for one item.
- Without Taken Pro the logging intents write nothing and answer "Logging needs Taken Pro. Open Taken to continue." The request is kept for 10 minutes in the App Group, and when Taken opens it offers it with the paywall (logged at the time it was asked for once Pro is on). `Did I take it?` always answers.

### 3.8 Data and correctness (code owns truth)
- Model: `Item { id: UUID, name, code, frequency (.daily(times: 1...3) | .alternateDays | .weekdays(Set<Int>)), createdAt, archived, archivedAt, sortIndex, pastFrequencies: [{ until, frequency }]?, pauses: [{ from, until }]? }`, `Dose { id, itemId, takenAt: Date, utcOffset: Int? }`. Day membership of a dose = calendar day of (takenAt - dayStartHour) at the UTC offset where it was logged (`utcOffset`; doses saved before it existed use the current zone). Each day uses the frequency in force that day. Everything computed from doses; no denormalized "done" flags.
- ALT DAYS: due today if never taken, or the last dose's day is 2+ days before today. If taken yesterday: not due, NEXT TOMORROW.
- Store: one Codable JSON file in the App Group container, written atomically, read/written through NSFileCoordinator so the app, widget and intents never clobber each other. A single `TakenStore` type (in a shared framework or shared source folder compiled into both targets) owns load/save/mutations and is the only writer. App reloads from disk on scenePhase .active and on a Darwin notification or file presenter callback when the widget writes.
- Timezone and DST: store absolute Dates plus the UTC offset each dose was logged at; compute today with the user's current calendar and the rollover hour, and each dose's day at its own offset, so travel never moves a dose to another day.
- Unit tests (XCTest target `TakenTests`) cover: day rollover, ALT DAYS due logic, weekday frequency, multi-dose completion, streak (incl. days with nothing due, today incomplete), 30-day %, take-all only touching pending due doses, undo, backfill on a past day, CSV export, store round-trip and concurrent writers.

### 3.9 Taken Pro (1.1, PRO.md)
- Products (App Store Connect, fixed ids): `com.tombaxter.taken.pro.yearly` (1 year, introductory week at no charge), `com.tombaxter.taken.pro.monthly` (1 month), `com.tombaxter.taken.pro.lifetime` (non-consumable). Group "Taken Pro": yearly level 1, monthly level 2. Prices, periods and the offer are always read from StoreKit, never written in the app.
- Entitlement: `Shared/Pro.swift` holds the pure rule (`Entitlement.evaluate`, unit tested): Pro when a verified, unrevoked subscription is live (introductory week and billing grace period included), the lifetime purchase is verified and unrevoked, or the customer is a founding member: a verified production `AppTransaction` whose `originalAppVersion` (the first download's build) is 1 to `FoundingMember.maxBuild` (7). Sandbox and TestFlight report "1.0" and never count. Lifetime and founding beat a subscription, so their cache never expires.
- `Taken/Pro/ProStore.swift` (`@MainActor`): listens to `Transaction.updates` from launch, finishes transactions, refreshes on every return to the foreground, and writes `{isPro, reason, checkedAt, expiresAt?, willRenew?, billingIssue}` to `pro.json` in the App Group, next to the log. A check without an app transaction (offline) never takes Pro away.
- The gate (`ProGate`, one rule for the app, widgets, control, intents and the nudge): Pro while the cached status is active (until `expiresAt`, or for good); no Pro needed while nothing has ever been logged (the first session); otherwise locked. Two refinements: in the app, nothing locks until StoreKit's first answer of the launch (at most 4 s), so a paying customer never sees a lock flash; and a log that already had doses when 1.1 first ran (an update from 1.0, where every App Store download is a founding member) is never locked before StoreKit has answered for it.
- First session: the first run is untouched (empty state, Add sheet, first dose lights up). About 1.5 s after the first dose ever (from anywhere: a dose logged from a widget brings it up the next time Taken opens), the paywall slides up once. It never comes back on its own.
- Paywall (`Taken/Pro/PaywallView.swift`): one sheet over whatever is open, no carousel or countdown. Header panel with the capsule mark, `TAKEN PRO`, "Keep your record." and the person's own day on the TODAY ruler; three mono bullets; plan cards (yearly selected, `7 DAYS ON US` tag while eligible, the billed amount most prominent, "about $1.67 / month" under it); `START 7 DAYS ON US` or `CONTINUE`; the terms line built from StoreKit values (`Shared/ProCopy.swift`, unit tested); Restore, Redeem code, Terms of Use and Privacy. Purchase through SwiftUI's `PurchaseAction`; success plays the lock-in (brackets, scanline, success haptic), closes, and applies the tap that opened it. Pending (Ask to Buy) and errors get a calm line, cancel gets nothing.
- Local testing: `Taken/Taken.storekit` (the three products, the group and the introductory week) is the scheme's Run action StoreKit configuration; it is never bundled.

## 4. Design language and looks ("dark mil-tech, biohacker, premium, minimal")

Signal, the default look, is lifted from Tom's own sites badline.ai and lupolabs.ai (same token system). Three more looks are chosen in Settings > LOOK (3.4): one tap each, never at first launch, and a look is named for its colour, never for who might pick it.

| --- | --- | --- | --- | --- | --- |
| SIGNAL (default) | `#08090A` dark | `#F4F4F5` | amber `#FFB000` | `#FFB000` | HUD |
| BLUSH | `#FBF6F3` warm off-white | ink `#2A2224` | muted rose `#D9667F` | deeper rose `#A8425C` | soft |
| PHOSPHOR | `#060908` green-black | `#EFF5F1` | green phosphor `#3DFF8A` | `#3DFF8A` | HUD |

Theme system (`Shared/Theme.swift`, compiled into the app and the widget extension):
- `ThemeID` (`signal`, `blush`, `phosphor`, `ice`) is the stored choice. `ThemeTokens` holds a look as numbers, `Theme` turns them into the colours plus the radius scale, the brackets and the glow, and is injected through the environment (`@Environment(\.theme)`). Views and widgets never name a colour of their own: `grep -rnE 'Color\((hex|red|white|\.sRGB)|Color\.(white|black|gray)|\.(white|black)\b|UIColor|0x[0-9A-Fa-f]{6}' Taken TakenWidgets Shared --include='*.swift' | grep -v Shared/Theme.swift` finds nothing (`Color.clear`, no colour at all, is the one literal left).
- Colour roles, every look: `bg`, `bgRaised`, `bgInset` (canvas, panels, insets); `fg`, `fgMuted`, `fgSubtle`, `fgFaint` (text, faint = index marks and dashed rings); `line`, `lineStrong`, `lineDash`, `tick` (hairlines, dashed rules, ruler ticks); `bracket` (HUD brackets at rest); `signal` (lit fills: discs, pips, segments, lamps, the glyph's lit half), `signalInk` (the signal as text and thin marks, AA on canvas, panels and the wash), `signalEdge`, `signalWash`, `onSignal` (the check on a lit disc); `button`, `buttonText`, `buttonLamp` (light button on the dark looks, ink button on Blush; the lamp on it is a deeper shade of the signal where the button is pale); `danger` (destructive confirms only).
- Signal tokens are 1.0's exactly: `bg #08090A`, `bgRaised #0F1012`, `bgInset #16171A`; `fg #F4F4F5`, `fgMuted #A1A1AA`, `fgSubtle #7C7C85`, `fgFaint #52525B`; `line rgba(255,255,255,0.10)`, `lineStrong rgba(255,255,255,0.18)`, `lineDash rgba(161,161,170,0.20)`, `tick rgba(161,161,170,0.34)`; `signal #FFB000`; `danger #FF5F57`. Lit = taken. Everything else is monochrome.
- Blush: canvas `#FBF6F3`, panels `#FFFDFB`, insets `#F3EBE7`; ink `#2A2224`, `#5F5357`, `#776A6E`, faint `#A5979B`; warm grey hairlines (ink at 10% and 18%); rose `#D9667F` for what is lit and `#A8425C` wherever the rose is text; white check on a lit disc; ink button with off-white type; danger `#C0392B`. Calm and premium: no gradients beyond the faint signal wash, a soft glow at 0.35 of Signal's.
- Phosphor and Ice are the Signal composition recoloured, with greys tinted toward their accent: Phosphor `#060908` / `#0C110E` / `#131915`, text `#EFF5F1` / `#9EAAA3` / `#78847D` / `#4E5852`, glow 0.85; Ice `#07090C` / `#0D1015` / `#14181E`, text `#F0F3F7` / `#A0A9B4` / `#7A838E` / `#4F5661`.
- Radius scale (`ThemeRadius`): frame (bracketed status panel, empty state, paywall header), panel (panels, buttons, toasts, cards), control (chips, code tags, fields, segmented controls, history cells), mark (plan radio, tags, PRO glyph), segment (progress bars), lamp roundness. HUD (Signal, Phosphor, Ice): 0, 4, 3, 2, 0, square lamps. Soft (Blush): 14, 12, 8, 4, 3, round lamps.
- Brackets (`ThemeBrackets`): HUD looks draw 1.5 pt square viewfinder corners; Blush draws delicate 1 pt brackets at 0.8 of the length, as arcs that follow the rounded frame, with round ends.
- Persistence: the look is `StackSettings.theme` in `taken.json`, the App Group store, so the widgets and the control read it with the stack. A file without it (1.0) or with a look this version does not know reads as Signal and loses nothing else; Erase all data keeps the look. Unit tests (`TakenTests/ThemeTests.swift`) cover decoding, the round trip, erase, the widget snapshot, the `-theme` launch argument, Signal's exact tokens, AA contrast for every look and the alternate icons in the bundle.
- Appearance: the root and every sheet set `preferredColorScheme(theme.scheme)`, so the status bar, menus, dialogs, pickers and system sheets follow the look. The launch screen stays `#08090A`; a light look fades in from it (0.4 s) instead of cutting to white.
- App icons: every look has its own icon, rendered by `brand/icon.py` from the same tokens (`--looks-sheet` writes a review sheet). Signal is the primary icon (`AppIcon`); `AppIcon-Blush` (the capsule in rose on off-white, delicate rounded brackets), `AppIcon-Phosphor` and `AppIcon-Ice` (the Signal composition recoloured) are alternate icons with dark and tinted variants, listed in `ASSETCATALOG_COMPILER_ALTERNATE_APPICON_NAMES`. Taken calls `setAlternateIconName` 0.6 s after the look changes (iOS confirms with its own alert; a few quick taps end in one change) and checks again on every return to the foreground.

Shared by every look:
- Type: Geist (sans) for names and body, Geist Mono for every number, code tag, label, timestamp, button. Both are SIL OFL fonts by Vercel: bundle the TTFs (download from the official npm package `geist` or github.com/vercel/geist-font releases) and register via UIAppFonts; include the OFL licence file. Labels are mono CAPS with generous letter-spacing (tracking ~0.12em). Numbers use monospaced digits.
- HUD details: 1 px hairlines, dashed separators, corner-bracket frames on the status header (viewfinder style), tiny tick-mark rulers, the look's corner radii, no drop shadows except a soft signal glow on lit elements. No emoji, no illustrations, no gradients except a faint signal glow.
- Motion: snappy (0.18 to 0.3 s), spring on the take tap, a scanline/sweep or bracket-snap on ALL TAKEN; a new look crossfades in 0.3 s. Respect Reduce Motion.
- Haptics: `.impact(light)` on take, `.success` notification on ALL TAKEN, `.selection` on chips and looks. Respect the HAPTICS toggle.
- Accessibility: Dynamic Type on body text (mono labels may cap at a sensible max), VoiceOver labels like "Vitamin D3, taken at 7:42 AM" / "Fish Oil, pending, double tap to mark taken" / "Blush look, selected", minimum 44 pt hit targets. Contrast AA for text in every look: `fg`, `fgMuted`, `fgSubtle`, `signalInk` and `danger` reach 4.5:1 on the canvas and on panels, `signalInk` on the wash, button type on its button; the check on a lit disc and a lit segment reach 3:1 (unit tested).
- Copy voice: terse, mono, confident. No em dashes in user-facing copy. Never the word "free". No exclamation marks.

## 6. Build and release (cloud only; Tom's Mac has no Xcode)

- Repo: github.com/tjbaxter/taken (public, so GitHub-hosted macOS runners cost nothing). Never commit secrets, certificates, profiles or .p8 keys. `.gitignore` covers *.p8, *.p12, *.mobileprovision, *.xcodeproj, build/, DerivedData.
- `.github/workflows/ci.yml` (push to main + workflow_dispatch, NOT pull_request_target): runner `macos-26`, select Xcode 26.x, `brew install xcodegen`, `xcodegen generate`, build + test on an iOS 26 iPhone simulator, then the screenshot job (see below) uploading `screenshots/*.png` as an artifact.
- Screenshots: the app accepts launch arguments `-demo` (seeds a realistic demo stack + 5 weeks of history into an in-memory/temporary store, never the real one) and `-screen <today|today-done|add|settings|look|day|log|widgets|empty|paywall|locked|widgets-locked>` to open straight onto a state, with `-theme <signal|blush|phosphor|ice>` for the look (CI captures today, today-done, log, paywall, widgets and LOOK in every look, and more of Blush, the light one). Under `-demo` Taken Pro never touches StoreKit: the store states show Pro, and `paywall` (yearly selected, introductory week available) and `locked` (TODAY without Pro) use StoreKit-shaped demo plans, because CI has no App Store account. Secrets: `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8_BASE64`, `DIST_CERT_P12_BASE64`, `DIST_CERT_PASSWORD`, `PROFILE_APP_BASE64`, `PROFILE_WIDGETS_BASE64`. Steps: temp keychain + import p12, install both profiles, `xcodegen generate`, archive Release for `generic/platform=iOS` with `CURRENT_PROJECT_VERSION=${{ github.run_number }}` and manual signing per target (CODE_SIGN_STYLE=Manual, PROVISIONING_PROFILE_SPECIFIER per target, CODE_SIGN_IDENTITY "Apple Distribution"), export with an ExportOptions.plist (method app-store-connect, manual signing, provisioningProfiles map for both bundle ids), upload with `xcrun altool --upload-app` using the API key (place the p8 at ~/.appstoreconnect/private_keys/AuthKey_<id>.p8), fall back to `xcodebuild -exportArchive` with `destination upload` + `-authenticationKeyPath/-authenticationKeyID/-authenticationKeyIssuerID`. Always delete the temp keychain and key in an `always()` step.
- Provisioning profile names (created by the release engineer): `Taken App Store` (com.tombaxter.taken) and `Taken Widgets App Store` (com.tombaxter.taken.widgets).
